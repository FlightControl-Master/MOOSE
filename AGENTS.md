# Code style

- Document new or changed methods completely in the existing MOOSE format, including all parameters, relevant units and defaults, and return values.
- Separate logical steps with blank lines so the code remains easy to read. Expand dense one-line blocks when that improves clarity.
- Add comments at relevant points explaining what is done and why, especially ownership, state changes, scheduling and non-obvious decisions. Follow the surrounding code's English comment style.
- Apply these conventions to future code additions and changes throughout this project.
